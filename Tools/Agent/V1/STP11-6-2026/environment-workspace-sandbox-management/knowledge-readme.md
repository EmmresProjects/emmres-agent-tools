# Environment, Workspace, Sandbox, and File Management — Skill Tool component

**Folder:** `environment-workspace-sandbox-management/` · **Primary entry point:** `environment-workspace-sandbox-management/tools-workspace.py` · **Scope:** 31 catalog categories, 310 named capabilities, 157 distinct route variants. This is a reusable **Skill Tool component** for placement beside a future skill-root `SKILL.md`; it is **not** a complete skill package and contains no `SKILL.md` itself.

## Purpose and honest capability boundaries

The attached *Environment, Workspace, Sandbox, and File Management Skill Catalog* proposes 310 skills, rather than providing implementations. This component unifies their related workspace-control tasks into one root-confined CLI. It implements actual local scanning, structural parsing, transfer/journaling/rollback, archive creation/extraction, staging, permissions, redaction, environment creation, offline package installation, trusted job execution, SQLite, workflow orchestration, checks, and evidence-backed planning. Every catalog name is addressable by exact slug or number. A name may map to a shared safe primitive; different names retain their roles, descriptions and example inputs in the registry and tables below.

**Mode in the catalog:** `action` means a real local operation is available after preflight and explicit matching approval; `inspection` performs a bounded read-only check; `assessment` produces a focused plan with observations, not the consequential action. Actions with missing services or a restrictive policy return `integration_unavailable` rather than success. Some broad proposals only have a **local, bounded subset** here (for example VM inventory rather than VM provisioning, static office inspection rather than visual review, and credential incident planning rather than provider-side rotation). Do not equate a successful local check with full compliance, security isolation, or a finished business workflow.

## Setup and exact commands

**Shell: Bash, working directory: future skill root.** Keep `environment-workspace-sandbox-management/` beside the parent root `SKILL.md`; create `workspace/` only for example runtime data. No install command is required for the tool itself. **Runtime requirement:** Python 3.11 or later with its standard library (including `tomllib`, `venv`, `sqlite3`); the validation environment used Python 3.13.16. Use a Python installation with `ensurepip` if creating a pip-enabled venv. POSIX procfs is needed for task-owned background-service start/status/stop. ### Actual approved transfer and recovery

The `--input` path is **relative to `--root`** and contains a JSON **object**. The `--output` report path is also root-relative, must have an existing parent, and must not replace different content. These runtime files are created by the operator; they are not packaged resources.

```bash
printf '%s\n' '{"source":"inputs/a.txt","destination":"working/a.txt","action":"copy"}' > workspace/reports/request.json
python3 environment-workspace-sandbox-management/tools-workspace.py run batch-move-and-copy-operator --root workspace --input reports/request.json --output reports/transfer-plan.json
python3 -c 'import json; print(json.load(open("workspace/reports/transfer-plan.json"))["result"]["approval_token"])'
# Review the plan and pass the freshly returned token exactly:
python3 environment-workspace-sandbox-management/tools-workspace.py run batch-move-and-copy-operator --root workspace --input reports/request.json --apply --approve "$(python3 -c 'import json; print(json.load(open("workspace/reports/transfer-plan.json"))["result"]["approval_token"])')"
python3 environment-workspace-sandbox-management/tools-workspace.py run copy-integrity-verifier --root workspace --input reports/request.json
```

The completed transfer result contains `transaction_id`. To undo an unchanged output, write `{"transaction_id":"..."}` to `workspace/reports/rollback.json`, run `file-operation-recovery-specialist` without `--apply` to review its token, then rerun with `--apply --approve` as above. **A token is a review/confirmation mechanism bound to the current plan, root, request and policy; it is not an authentication credential or an OS security boundary.** Source files under `uploads/`, `inputs/`, `sources/`, and `originals/` can be **copied**, not moved/replaced. New reviewed outputs may be promoted to `deliverables/` or `final/`; existing final artifacts cannot be replaced through normal transfers.

**Output structure is JSON, not prose.** Files created by an approved operation include their path, checksum or transaction ID when applicable. Inspection results include explicit `valid`, `ready`, `findings`, `note` or `unavailable_integration` as appropriate; no UI rendering or receipt proof is implied. Timestamps in reports are UTC; snapshots include file mtimes and current disk status, so their entire JSON is not byte-identical across runs. ZIP archives generated from the same unchanged inputs are made with stable member order and fixed ZIP timestamps; external tools can still vary.

## Policy, approvals, limits, cancellation and recovery

- **Boundary:** All requested paths must be relative POSIX paths inside `--root` (except the literal `.` for scanning). Reject absolute, drive-letter, parent-traversal and symlink components. Scans never follow symlinks; ZIP extraction rejects traversal, drive paths, symlinks, duplicate/case-colliding names, excessive expansion and suspicious compression ratios. A same-user concurrent adversary can still race portable filesystem checks; this is not kernel sandboxing.
- **Preservation:** Default protected prefixes are `uploads`, `inputs`, `sources`, `originals`, `deliverables`, `final`, plus internal state. Original inputs are copied, not moved/overwritten. Consequential operations require a fresh review token, prevent collisions or back up a requested replacement, journal recoverable transfers, and prefer new outputs. Permanent purge is available only for a previously quarantined copy after the configured retention window and separate approval. Quarantine/rollback can be blocked if bytes changed.
- **Secrets:** Discovery is heuristic and returns locations/types, not secret values. Text redaction writes a NEW UTF-8 copy and never edits the original. Activity events are scrubbed before private hash-chained storage. Restrict runtime state; private job logs might still contain raw external program output and must be reviewed/sanitized before handoff. Do not put credentials in command-line args, policy profiles, output paths, or bundled resources. External credential issuance/revocation is not implemented.
- **Default limits:** 5,000 scan entries; 16 levels; 256 KiB input JSON; 1 MiB inspected text per file; 32 MiB hashed scan file; 512 MiB file transfer or archive; 2,000 ZIP members; 60 s external command; 64 KiB returned stdout/stderr per stream; two retries for safe transient failures; 32 workflow stages; seven-day quarantine retention. Policy overrides cannot exceed hard-coded ceilings (20,000 entries, depth 32, 300 s command, 2 GiB transfer/archive); smaller limits are encouraged. Scan an explicit subset in very large workspaces.
- **Timeout and cancellation:** External foreground commands are bounded and their owned process group is terminated on timeout or Ctrl+C. Workflow checks the runtime `.workspace-control/cancel` marker between stages; deleting that marker after review allows a fresh resume. Background services are Linux/POSIX procfs-owned, require a job record and explicit stop, report overdue runtime, and are **not** persistent cron jobs. Scheduled jobs run at most five times within a 300 s budget; only read-only independent DAG stages may run in parallel. Stop task-owned services before leaving the workspace.
- **Recovery:** An interrupted file transaction records finished steps in `.workspace-control/transaction-*.json`; first inspect the affected paths and journal, then use `file-operation-recovery-specialist` with its real returned transaction ID. A workflow stores `.workspace-control/workflow-<workflow_id>.json`; inspect `orchestration-recovery-specialist`, repair the earliest failure, rerun `checkpoint-and-resume-manager` with fresh approval. Read-only stages may retry transient failures; consequential stages do not auto-retry. A log chain can detect accidental alteration, not a malicious full rewrite. Preserve external backups for disaster recovery.
- **Privileged/global actions:** No automatic global package-manager operation, ownership change, public port exposure, OS trust-store modification, credential rotation, publication, payment, signing, arbitrary shell, or untrusted executable analysis. Optional container use requires explicit policy opt-in and approval; a Docker daemon/socket can confer host privileges even with restrictive container flags. VM creation and snapshots require a separately approved hypervisor + OS image and are **not implemented** here; only optional session inventory is wired.

## Troubleshooting, extension and maintenance

| Symptom | Correct response |
| --- | --- |
| `missing_input`, `invalid_input`, or `unsafe_path` | Check that the JSON file and its referenced objects exist under the chosen `--root`, use forward slashes, inspect extension/signature, and limit file size; do not bypass symlink guards. |
| `collision`, `changed_input`, or changed approval token | Stop, inspect the destination/current hashes, capture a new plan, and approve only the revised action; do not overwrite originals to make a test pass. |
| `approval_required` | Review path list, hashes, conflict policy and risk. Rerun with `--apply --approve` using the token from the **same unchanged plan**. A token is not an identity or permission grant. |
| `integration_unavailable` | Check local executable/runtime/license/service; keep policy off by default. Use independent local inspection or document the blocker. A valid local package cannot cure a remote hosting/catalog/permission outage. |
| `limit_exceeded` | Narrow `paths`, lower batch size, split work; only increase trusted policy limits within hard bounds after resource review. |
| `verification_failed` / `transaction_interrupted` | Preserve state, isolate earliest failing operation, compare hashes and journal/checkpoint, use reviewed rollback/resume; do not purge backups or task logs under investigation. |
| Broken final rendering or missing external fonts | Run an actual approved renderer in the recipient environment and inspect the output. Structural ZIP/XML/PDF checks are not visual or accessibility tests. |

To extend behavior, edit the existing route handler in the appropriate prefixed module under `environment-workspace-sandbox-management/`, update `environment-workspace-sandbox-management/asset-capabilities.json` IDs/routes/modes and the single knowledge table, add an executable regression to `environment-workspace-sandbox-management/tools-selftest.py`, then repeat clean-root and extracted-ZIP tests. Configuration/policies live in JSON, not hard-coded secrets or tenant paths. Preserve stable lowercase filenames and all relative, case-sensitive references. For novel service providers, implement an opt-in adapter with explicit permissions, timeouts, bounded input/output and verification; document untested paths rather than advertising support.
