# document-productivity Skill Tool

This is the consolidated operational guide for the reusable component in `/document-productivity` and the only knowledge file in the package.

## Purpose

`document-productivity` is one reusable Copilot Skill Tool component built from the supplied **Comprehensive Document and Productivity Skill Catalog**. The catalog defines 36 categories and 784 named capabilities. This component combines all related listed capabilities into one unified tool folder rather than creating 36 or 784 separate packages. It is a component of a future skill, not a complete skill: it contains no `SKILL.md` and no `Skills.zip`.

The tool parses a single capability, a numbered Skill Tool list, one category, or several categories from plain text, Markdown, or copied HTML. It ignores HTML tags, CSS classes, data attributes, numbering marks, running PDF headers, and extra spacing. When a category or index appears without individual items, it expands that category from the bundled catalog. When no category label exists, it derives a short lowercase hyphenated umbrella name from the shared purpose. The normalized source becomes one plan with one `tool_name`, not a menu of packages.

Every one of the 784 exact Skill Tool Names is retained in `/document-productivity/asset-capability-catalog.json`, is listed by `capabilities`, is explained by `explain`, and is reachable through `run --capability`. The 36 category operations are distinct handlers; overlapping descriptions share validation, input reading, provider selection, prompt selection, approval, limits, atomic writes, and artifact inspection through `tools-operations.py`.

Hyphenated filenames are loaded through `importlib.util.spec_from_file_location`, so no package installation or filename rename is needed.

## Setup and dependencies

- Runtime: Python 3.10 or newer. The implementation was checked with Python 3.13 using only the standard library.
- Third-party packages: none required, none declared, none installed by this component.
- Install command: none. Python 3.10 or newer with its standard library is sufficient; no dependency file or network installation is needed.
- Optional external libraries: none are loaded. Office files are generated and inspected as OOXML/ODF ZIP packages with `zipfile` and `xml.etree.ElementTree`; PDFs are generated as bounded PDF 1.4 files with a standard-library byte writer.
- Permissions: read access to configured input paths and write access to configured output paths outside the Skill Tool folder.
- Credentials: none. Approval tokens are read only from the environment variable named in `/asset-default-config.json`; no token value is packaged.
- Network: disabled by default in `/asset-default-config.json` and `/asset-safety-policy.json`.

No shell is required; every command below names `python3` explicitly. If a host requires a shell, use `bash` with the same explicit interpreter, for example `bash -c "python3 /document-productivity/tools-document-productivity.py capabilities"`.

Copy `/document-productivity` directly beside the future parent package's root `SKILL.md`. The combined package then has exactly one root `SKILL.md`, this folder at level one, and its files at level two. Leading-slash references are skill-root relative, not filesystem absolute: `/asset-default-config.json` and `/document-productivity/asset-default-config.json` both resolve to the same packaged file. Use forward slashes and exact case. Do not rewrite references after copying.

## Inputs, outputs, parameters, and schemas

`parse` and `plan` accept either `--input` or `--text`. Accepted source formats are detected automatically: plain text, Markdown, or copied HTML. HTML style/script content, classes, and data attributes are discarded. Numbered list marks such as `1.`, `2)`, bullets, Markdown headings, emphasis, links, and extra spaces are normalized. Category index lines such as `5. PDF Engineering (30 skills)` are recognized. Category-only sources expand from the bundled catalog unless `--no-expand-categories` is supplied.

`run`, `batch`, and `convert` accept input and output paths. `--input` may be a file or directory; `--output` may be a recognized artifact path or an output directory. `--report` controls the structured JSON result path. `--format` selects the primary artifact format; if omitted, a recognized `--output` extension is used, otherwise the capability's default format is used. Supported primary formats are `json`, `csv`, `html`, `md`, `txt`, `css`, `svg`, `pdf`, `docx`, `xlsx`, `odt`, `ods`, and `zip`. `--options` accepts an inline JSON object and `--options-file` accepts a JSON object file. Shortcut flags such as `--to`, `--formula`, `--provider`, `--prompt-set`, `--locale`, `--theme`, `--value-column`, `--label-column`, `--chart-type`, `--series-name`, `--retention`, and `--citation-style` are merged into the options object.

Every operation writes a primary artifact, zero or more extra artifacts, and a structured JSON report. The report records `ok`, `command`, capability identity, category, operation, handler, action, input, output, format, dry-run state, approval, policy, providers, prompts, artifact paths/bytes/hashes, checks, errors, warnings, metrics, limits, recovery, and payload summary. Errors are structured JSON with a code, message, details, and a nonzero exit code. Dry runs render all artifacts in memory and write nothing.

`/asset-json-schemas.json` defines the shapes used by `validate`: `config`, `catalog`, `source`, `plan`, `result`, `batch`, `json`, and `artifact`. `tools-safety.py` implements a deterministic JSON-Schema subset supporting type, enum, required, properties, items, minimum, maximum, minLength, pattern, additionalProperties, and local definition references. No external schema validator is used.

`/asset-default-config.json` is the main configuration. Important keys:

- `catalog_path`, `source_catalog_path`, `policy_path`, `provider_presets_path`, `prompt_set_path`, `schemas_path`, `document_template_path`, `sample_data_path`: stable root-relative internal paths.
- `limits.max_input_bytes`, `limits.max_output_bytes`, `limits.max_files`, `limits.max_text_chars`, `limits.max_formula_chars`, `limits.max_ast_nodes`, `limits.timeout_seconds`, `limits.retry_count`, `limits.retry_delay_ms`, `limits.max_capabilities_per_batch`, `limits.max_path_depth`, and `limits.max_package_files`.
- `providers.default`, `providers.network_enabled`, `providers.allow_remote_calls`, `providers.request_timeout_seconds`.
- `models.default`, `models.remote`, `models.temperature`: provider/model settings are configurable; no remote model is called.
- `prompts.default_set`, `prompts.require_grounded_input`, `prompts.require_human_approval`.
- `policies.require_approval_for_sensitive`, `policies.dry_run_skips_writes`, `policies.atomic_writes`.
- `storage.root`, `storage.atomic`, `storage.backup`, `storage.backup_suffix`, `storage.temp_dir`, `storage.cleanup_temp`.
- `approval.token_env`, `approval.reason_required`.
- `network.enabled`, `network.allowed_hosts`.

Use `--set` for a one-command override, for example `--set storage.root=./custom-out` or `--set limits.timeout_seconds=180`. Use a modified copy of `/asset-default-config.json` with `--config` for persistent overrides. Every configurable path remains relative to the future skill root or supplied at runtime; no machine-specific path is packaged.

## Safety, approval, and bounded execution

`/asset-safety-policy.json` classifies destructive, irreversible, privileged, publishing, financial, credential, security, and integration actions. Catalog entries also carry precomputed `approval_classes`. `run`, `batch`, `convert`, `recover`, and structured-output overwrites call one shared approval gate before writes. No token value is stored in the package. Configure the environment variable named by `approval.token_env`, default `DOCUMENT_PRODUCTIVITY_APPROVAL_TOKEN`, and pass `--approval-token` plus `--approval-reason`. Dry runs of sensitive capabilities are allowed because they write nothing; their result says `deferred-dry-run`.

Blocked actions include arbitrary code execution, shell execution, network requests, password encryption, digital signatures, credential storage, financial transactions, remote publishing, external workspace writes, external drive writes, and external sheet writes. Formula evaluation uses an AST whitelist with numeric literals, input column names, numeric constants, arithmetic operators, and a small math-function allowlist. It rejects private names, imports, semicolons, lambdas, attributes, subscripts, unknown names, oversized expressions, unsafe exponents, division by zero, and non-finite results. No `eval`, `exec`, macro, VBA, Apps Script, Office Script, Power Query M, DAX, webhook, API call, or subprocess is used by capability handlers. The only subprocess use is `selftest`, which calls the same CLI with `python3` and `shell=False`.

`RunGuard` enforces `limits.timeout_seconds` with a wall-clock alarm where available and cooperative checks in all loops and file scans. SIGINT is mapped to structured cancellation. `atomic_write` writes a temporary file in the destination directory, flushes it, replaces the target atomically, creates a `.bak` backup before approved overwrites, restores the backup on write failure, and removes `.partial` and temporary files. `recover` restores a backup after approval. `batch` uses one shared guard and a configurable `max_capabilities_per_batch`.

## Limits and unavailable integrations

Implemented locally: source parsing and unified planning; 36 category handlers; 784 capability identities; safe arithmetic formulas; structured JSON reports; CSV, JSON, HTML, Markdown, text, CSS, SVG, PDF, DOCX, XLSX, ODT, ODS, and ZIP generation; ZIP/XML/CRC/PDF/SVG/CSV/JSON/HTML/text inspection; atomic writes; backups; recovery; retries; cancellation; timeout; approval; configurable providers, models, prompts, policies, paths, limits, and storage. Standard W3C, OOXML, ODF, and Dublin Core XML namespace identifiers embedded in generated SVG/OOXML/ODF files are fixed format identifiers, never dereferenced or fetched; no HTTP client is loaded and no network request is made.

Not implemented and intentionally not claimed: live Microsoft 365, Google Workspace, Canva, Adobe Acrobat, Microsoft Graph, Google Docs API, Google Sheets API, SharePoint, OneDrive, Power Automate, Power Apps, CRM, ERP, database, webhook, VBA, Office Scripts, Apps Script, Power Query M, DAX, cube formulas, or electronic-signature execution. `/asset-provider-presets.json` records these as disabled plan-only providers with no endpoints or credential values.

Format-specific limitations: PDF text extraction handles literal strings in readable streams only; no OCR, password encryption, digital signature, rights management, PDF/A certification, or full PDF repair. DOCX/XLSX/ODT/ODS writers are minimal but valid editable packages; they do not reproduce vendor-specific macros, pivot caches, external links, charts embedded as native objects, or complex style inheritance. SVG output is standalone and sanitized. HTML uses inline CSS only. The accessibility audit is structural, not WCAG certification. Automated contrast computation, screen-reader rendering, keyboard testing, visual regression, mobile viewing, and cross-platform rendering require external viewers. Legacy `.doc`, `.xls`, RTF, image-to-editable conversion, scanned-table OCR, machine translation, and remote suite migration are unavailable. Financial and accounting outputs are calculation models and schedules, not advice, filings, payments, or transactions. Legal, HR, medical, engineering, and clinical scenarios are formatting aids requiring human professionals.

Other limits: `max_input_bytes` defaults to 52428800, `max_output_bytes` to 104857600, `max_files` to 1000, `max_text_chars` to 2000000, `max_formula_chars` to 500, `max_ast_nodes` to 120, `timeout_seconds` to 60, `retry_count` to 2, `retry_delay_ms` to 100, `max_capabilities_per_batch` to 1000, `max_path_depth` to 3, and `max_package_files` to 500. All are configurable in `/asset-default-config.json` or with `--set`.

## Troubleshooting, recovery, extension, and maintenance

- `config_not_found`, `catalog_not_found`, or `policy_not_found`: check the root-relative path in `/asset-default-config.json` or pass `--config`, `--catalog`, or `--policy`.
- `unknown_capability`: run `capabilities --query WORD` or `explain --capability EXACT NAME`; use the id or global slug for ambiguous names.
- `ambiguous_capability`: the exact label `Excel VBA Automation` is preserved in two categories; use `c07-s18`, `c30-s04`, or a global slug from `capabilities` to select the intended responsibility.
- `category_expansion_disabled`: a category-only source with `--no-expand-categories` has no listed capabilities to parse; either list explicit Skill Tool Names or omit the flag to expand from the bundled catalog.
- `format_not_supported_for_capability`: run `explain --capability EXACT NAME` to see supported formats, or choose another capability.
- `input_not_found` or `input_required`: supply `--input`; directories are supported, symlinks are rejected.
- `approval_denied` or `approval_token_not_configured`: set the configured environment variable and pass `--approval-token` plus `--approval-reason`. For a review-only check, use `--dry-run`.
- `output_exists`: choose a new path or use `--overwrite` with approval. A `.bak` backup is created.
- `backup_exists`: run `recover` or choose another output path before overwriting again.
- `timeout` or `cancelled`: reduce input size, narrow a batch with `--limit`, or raise `limits.timeout_seconds` with `--set`. Cancellation is structured and safe because writes are atomic.
- `invalid_formula` or `unsafe_formula`: use only numeric column names, numeric constants, arithmetic operators, and allowed math functions; avoid code, imports, attributes, and private names.
- `output_inside_package`: choose a destination outside `/document-productivity`; this protects the reusable component from runtime artifacts.
- `package_check_failed`: use `verify --output ./out/verify.json` to see the exact failed check, then update the affected filename or reference consistently.

Recovery example:

```text
DOCUMENT_PRODUCTIVITY_APPROVAL_TOKEN=local-token python3 /document-productivity/tools-document-productivity.py recover --backup ./out/report.json.bak --output ./out/restored.json --overwrite --approval-token local-token --approval-reason "restore after failed write"
```

Use environment-specific token values only at runtime; never edit a token into `/asset-default-config.json`.

To extend the tool, add a new capability record to a copy of `/asset-capability-catalog.json`, add a handler function beginning with `op_` to `tools-category-handlers.py`, include it in `HANDLERS`, document its filename and responsibility here, and rerun `handlers`, `verify`, and `selftest`. To add a format, implement a writer and validator in `tools-formats.py`, add the extension to `SUPPORTED_FORMATS`, update affected `supported_formats` lists, and rerun the all-format portion of `selftest`. To change approval behavior, edit `/asset-safety-policy.json` and rerun the approval and recovery tests. To change providers or prompts, edit `/asset-provider-presets.json` or `/asset-prompt-set.json`; keep endpoints and credentials unset unless an externally approved adapter is added outside this component.

Maintenance rules: keep all files directly inside `/document-productivity`; keep every filename prefixed with `tools-`, `knowledge-`, or `asset-`; keep exactly one `knowledge-readme.md`; keep every internal reference root-relative with forward slashes and exact case; never add a nested folder, nested archive, `SKILL.md`, raw log, cache, failed output, or machine-specific path; and update every reference whenever a file is renamed, moved, or removed. The delivered folder has 20 files, no subfolders, and no nested archives, so it stays well within the 500-file and three-level package limits.
