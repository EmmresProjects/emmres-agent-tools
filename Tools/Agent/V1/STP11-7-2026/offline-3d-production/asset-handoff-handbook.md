# Department Handoff Handbook (fill-in reference)

Use this handbook with `asset-handoff-template.json`. It is a production checklist, not
tool documentation; the operational guide is `knowledge-readme.md`.

## 1. Before any handoff

- [ ] Names pass the naming standard: `python tools-o3d.py validate names --names-file names.txt`
- [ ] Geometry passes its gate: `python tools-o3d.py validate geometry --mesh <mesh>`
- [ ] Animation passes its gate: `python tools-o3d.py validate animation --curves <curves.json>`
- [ ] Licence and consent records are current: `python tools-o3d.py license audit --assets <assets.json>`
- [ ] Every binary deliverable has a SHA-256 digest: `python tools-o3d.py hash --file <file>`
- [ ] The delivery folder passes: `python tools-o3d.py validate package --dir 15-delivery`

## 2. Contract that must match on both sides

| Contract | Where it lives | Failure symptom |
| --- | --- | --- |
| Units and scale | `asset-default-config.json` → `project.units` | Rig behaves like a giant or an ant |
| Up axis / forward | `project.up_axis`, `project.forward_axis` | Character lies down or faces away |
| Frame rate | `project.fps` | Foot sliding, sync drift |
| Frame range and handles | `animation.frame_start/frame_end` | Handles trimmed off, cut shots |
| Colour management | `project.color_management` | Washed-out or crushed textures |
| Naming standard | `standards naming` output | Broken links, duplicate datablocks |
| Texture channel order | `texture.channel_order` | Metallic/roughness swapped in engine |

## 3. Department-specific minimums

### Modeling → Rigging
Mesh is a single watertight object, transforms applied, subdivided levels either frozen or
documented, symmetry along the agreed axis, deformation zones free of poles, and a
`polygon_budget` block filled in the handoff.

### Rigging → Animation
Rest pose documented, control map included, space-switch behaviour described, joint limits
recorded, and the rig validation JSON attached. Animators must be able to reset to rest pose
with one documented action.

### Animation → Lighting / FX
Curves baked or keyframe-interpolated per the export profile, root motion either kept or
stripped (say which), contacts marked, and clip lengths matching the shot manifest.

### Texturing → Look-dev
Channel order matches `texture.channel_order`, dilation is at least 8 px, UDIM tiles are
complete, and every map is listed with its role so nothing is guessed from the filename.

### Any department → Delivery
Package gate passes, README present, licence fields filled for every third-party asset, and
the provenance record exists for anything generated by a neural model.

## 4. What "approved" means

An approval is only valid when it names: the file version, the reviewer, the date and the gate
JSON digest it was reviewed against. "Looks fine" in chat is not an approval record.

## 5. Recovery when a handoff fails

1. Re-run the failing gate and capture its JSON.
2. Fix the smallest possible thing (usually a name, a scale, or a missing map).
3. Re-run the gate; do not hand-edit the JSON to make it pass.
4. If the gate itself is wrong, record the exception in `known_limitations` with the reason and
   the approver, then change the profile in the configuration so the exception is explicit.
