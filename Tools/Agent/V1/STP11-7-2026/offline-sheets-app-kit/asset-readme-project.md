## How the data works

* Every record carries `Record ID`, `Branch ID`, `Account ID`, date and time.
* Records are written to the device first → **Pending** → **Sent** (or **Needs
  Review**). Nothing is lost when the wifi drops.
* `RecordID` is the identity: re-sending an order updates its row instead of
  adding a duplicate.
* Non-revenue entries ({{NONREV_LABELS}}) are counted, never added to revenue.

## Security notes

* Passwords are stored as `sha256$` + SHA-256(salt + "|" + password). No plain
  text password is ever written to the sheet or the device.
* The Apps Script endpoint is protected by `ACCESS_TOKEN`. This project ships with
  `{{DEFAULT_TOKEN}}`, which the backend refuses. Set your own in `Config.gs`.
* Login attempts, sends and voids are all logged in `SyncLog`.

## Re-generating with different content

This project came from a specification file. Keep that file next to the project;
editing it and re-running the generator is far safer than hand-editing 15 JS files.

```bash
python <kit>/tools-generate-kit.py new --spec spec.json --out ./my-app --force
```
