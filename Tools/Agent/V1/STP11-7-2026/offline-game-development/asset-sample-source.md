# Sample catalog source

A miniature catalog in the two shapes teams most often paste in: a Markdown list with
`Skill Name` and `Description` lines, and the same content copied out of an HTML table.
`import --source` reads this file and produces the same dataset shape as the bundled
`offline-game-development/asset-catalog.json`, so it doubles as the ingest test fixture.
Ten capabilities in two categories.

## 1. Offline Test Harness

4 skill concepts

### 1.1 Headless Engine Runner

Skill Name: Headless Engine Runner

Description: Implement headless engine runner as a focused reusable game-development capability with declared inputs and outputs, offline dependencies, rights metadata, performance budgets, diagnostics, tests, and target-build acceptance criteria.

### 1.2 Frozen Reference Cases

Skill Name: Frozen Reference Cases

Description: Define frozen reference cases with prerequisites, owners, platform and engine constraints, ordered steps, license gates, quality budgets, fallback paths, required evidence, and a verified completion condition.

### 1.3 Engine Log Scraper

Skill Name: Engine Log Scraper

Description: Create engine log scraper from pinned local inputs with license and integrity checks, deterministic settings, platform metadata, rollback or cleanup behavior, and a post-build import, launch, or playback validation.

### 1.4 Determinism Check

Skill Name: Determinism Check

Description: Evaluate determinism check with repeatable automated and manual checks, record the engine, platform, hardware, scene or build, measured result, pass threshold, failure evidence, and exact remediation and regression retest.
