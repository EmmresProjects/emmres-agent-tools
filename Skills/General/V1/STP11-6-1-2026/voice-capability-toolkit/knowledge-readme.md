# voice-capability-toolkit

A reusable Skill Tool for professional voice work. It parses voice capability lists, builds
implementation blueprints from them, and implements the operational core behind those
blueprints: voice identity design, script performance, pronunciation control, cleanup and
mastering, delivery validation, and measurement/diagnostics — with consent, disclosure and
provenance gates that block unsafe or unauthorized use.

This folder is **a Skill Tool component**, not a complete Copilot skill. It contains no
`SKILL.md`; it is designed to be copied beside a parent package's root `SKILL.md`.

Everything is local: no network calls, no shell execution, no credentials, no paid services.

## 1. Capability list

### 1.1 Tools (runnable entry points)

| File | Role | Entry point? |
|------|------|--------------|
| `tools-catalog-builder.py` | **Primary entry point.** Parses capability lists (plain text, Markdown, copied HTML, JSON, PDF when `pypdf` is installed) and builds recipe-driven implementation blueprints. | yes |
| `tools-voice-profile.py` | Voice identity design, profiles, variants, reference boards, consent verification, use-rights enforcement, enrollment, revocation. | yes |
| `tools-audio-synthesis.py` | Text-to-speech performance: prosody, emotion/attitude, effects, pronunciation dictionaries, text normalization, brief rendering, batch. | yes |
| `tools-audio-delivery.py` | Repair, mixing, mastering, format/preset encoding, cue sheets, manifests, package validation, checklists. | yes |
| `tools-audio-analysis.py` | Measurement, VAD, diarization, alignment, artifact detection, environment estimation, suitability scoring, A/B comparison, diagnostics. | yes |
| `tools-selftest.py` | Self-test suite that drives the real CLI of every other tool (36 checks). | yes |
| `tools-runtime-common.py` | Shared runtime: result envelope, structured errors/exit codes, resource resolution, approval gate, JSON-Schema subset validator, hashing, deadlines, timecode helpers. | no (loaded by all) |
| `tools-audio-engine.py` | Shared audio engine: I/O, measurement (loudness, true peak, pitch, VAD, noise, artifacts), DSP (EQ, denoise, gate, compressor, limiter, echo, drive, resample), formant synthesis, prosody planning, effect racks. | no (loaded by synthesis/delivery/analysis/selftest) |

Loading order: `tools-catalog-builder.py` → `tools-voice-profile.py` → `tools-audio-synthesis.py`
→ `tools-audio-delivery.py` → `tools-audio-analysis.py` → `tools-selftest.py`
(each user-facing tool loads `tools-runtime-common.py` and, where needed,
`tools-audio-engine.py`, via `importlib` from the same folder).

## 2. Setup and dependencies

### 2.1 Required

* **Python 3.9+** (developed and tested on CPython 3.13).
* `numpy >= 1.24` — DSP and measurement.
* `soundfile >= 0.12` (with the `libsndfile` system library) — audio I/O for WAV, FLAC,
  OGG/Opus, MP3 and AIFF.

```bash
# Debian/Ubuntu
sudo apt-get install -y libsndfile1
python3 -m pip install "numpy>=1.24" "soundfile>=0.12"
```

### 2.2 Optional

* `pypdf >= 3.9` — only for `tools-catalog-builder.py extract/build --input file.pdf`.
  Without it, PDF input returns exit code `6` with a `pip install pypdf` hint instead of
  crashing.
* `scipy` — optional accelerator. When SciPy is already installed the biquad filters use
  `scipy.signal.lfilter` (roughly 40× faster loudness measurement on multi-minute files);
  without it the tools fall back to a pure-NumPy implementation. Results agree within
  float tolerance either way, so SciPy is never required.

```bash
python3 -m pip install "pypdf>=3.9"
```

There is no separate dependency file: the runtime needs no build step, no virtualenv layout
and no package declaration. Everything else is Python standard library.

### 2.3 Sanity check

```bash
python3 voice-capability-toolkit/tools-selftest.py run --quick
```

The full suite runs 36 checks in about 55 seconds (63 s without SciPy) and needs roughly
40 MB of temporary space. `--quick` skips the three slowest delivery checks but still builds
the artifacts the dependent tests need, so it runs 33 checks with **0 skipped** in about 36
seconds. Work files go to a temporary directory that is deleted afterwards unless you pass
`--keep`. A test whose prerequisite artifact is genuinely missing (for example with
`--only`) is reported as `skipped` with a reason, never silently dropped. Work files go to a temporary directory that is deleted afterwards unless you
pass `--keep`; the tool sets `PYTHONDONTWRITEBYTECODE` so no `__pycache__` is ever created
beside the shipped files.

## 3. Command reference

All commands assume the current directory is the **future skill root** (the folder that also
holds `SKILL.md`). `--assets-dir` is accepted by every command if the asset files live
elsewhere.

Every command prints one JSON envelope on stdout:

```json
{"status": "ok", "toolkit": "voice-capability-toolkit", "version": "1.0.0", ...}
```

and returns a stable exit code (§6). `--output <file>` writes the same JSON to a file;
`--quiet` suppresses stdout.

### 3.1 `tools-catalog-builder.py` (primary entry point)

```bash
python3 voice-capability-toolkit/tools-catalog-builder.py --help
python3 voice-capability-toolkit/tools-catalog-builder.py capabilities
```

| Command | What it does | Key options |
|---------|--------------|-------------|
| `extract` | Parse capability text → catalog JSON. Handles numbered lists, bullets, `Skill Name:`/`Description:` pairs, Markdown headings, Markdown and HTML tables, PDF page furniture, wrapped lines, numbering marks and HTML attributes. | `--input/--text/stdin`, `--output-catalog`, `--category`, `--heading-mode {auto,always,never}` |
| `build` | Generate implementation blueprints using `asset-build-recipes.json`. | `--input catalog.json`, `--emit {umbrella,per-capability}`, `--umbrella`, `--categories`, `--skills`, `--out-dir`, `--format {md,json,both}`, `--max-documents` |
| `validate` | Validate any JSON document against `asset-schemas.json`. | `--input`, `--schema` (auto-inferred when omitted) |
| `lookup` | Search capabilities by keyword/category. | `--catalog`, `--query`, `--category` |
| `capabilities` | Machine-readable command index. | — |

Examples:

```bash
# Parse a capability list from Markdown
python3 voice-capability-toolkit/tools-catalog-builder.py extract \
  --input my-capability-list.md --output-catalog catalog.json

# Parse copied HTML (tags, classes and data attributes are ignored)
python3 voice-capability-toolkit/tools-catalog-builder.py extract \
  --input copied-page.html --output-catalog catalog.json

# Built-in 200-capability catalog → one blueprint per category
python3 voice-capability-toolkit/tools-catalog-builder.py build \
  --input voice-capability-toolkit/asset-catalog.json \
  --out-dir out/blueprints --format both

# Narrow to two capabilities, one blueprint each
python3 voice-capability-toolkit/tools-catalog-builder.py build \
  --input catalog.json --skills "Delivery Package Validator" "Voice Consent Verifier" \
  --emit per-capability --out-dir out/single

# Find everything about loudness
python3 voice-capability-toolkit/tools-catalog-builder.py lookup \
  --catalog catalog.json --query loudness
```

The 200-capability PDF shipped as the source document extracts exactly:

```bash
python3 -m pip install pypdf            # once
python3 voice-capability-toolkit/tools-catalog-builder.py extract \
  --input Ultimate_Voice_Skill_Catalog.pdf --output-catalog catalog.json
# → 20 categories, 200 capabilities, 0 schema problems
```

### 3.2 `tools-voice-profile.py`

```bash
python3 voice-capability-toolkit/tools-voice-profile.py capabilities
```

| Command | Purpose |
|---------|---------|
| `create` | Build a validated profile from `--brief <json>`, `--text "<description>"`, `--name "<name>"` or `--sample`. |
| `validate` | Validate a profile, consent record, brief, request, manifest or dictionary. |
| `plan` | Full performance plan for a script: per-segment syllabification, pitch targets, pauses, duration, disclosure. |
| `variants` | Deterministic variants along `--axis mood|age|language|context|energy`. |
| `reference-board` | Target traits, forbidden traits, measurable targets, sample lines, criteria; `--output-md` writes Markdown. |
| `verify-consent` | Verify consent structure, signature, expiry and scope against a request. Blocks with exit `5` when out of scope. |
| `check-use` | Enforce origin policy + profile rights + consent scope for a requested use. |
| `enroll` | Append an approved consent record to a local store with a hash chain. |
| `revoke` | Revoke a profile and list dependent assets (requires `--approve`). |

Examples:

```bash
# Design an original voice
python3 voice-capability-toolkit/tools-voice-profile.py create \
  --text "warm, elegant, 165hz, en-US, adult narrator" \
  --name "Aurora Host" --out-dir out

python3 voice-capability-toolkit/tools-voice-profile.py plan \
  --profile out/asset-aurora-host-profile.json \
  --text "We shipped the first version in March. It was fast, but it was not honest." \
  --emotion concern --intensity 0.6

# Rights check before any conversion or publish
python3 voice-capability-toolkit/tools-voice-profile.py check-use \
  --profile out/asset-aurora-host-profile.json \
  --request asset-fixtures.json#usage_request_example \
  --consent asset-fixtures.json#consent_example
```

`file.json#key` selects a named sub-document, which makes the fixtures reusable directly.

### 4.2 Schemas (`asset-schemas.json`)

`schema_for()` + `validate_schema()` implement a JSON-Schema subset: `type`, `required`,
`properties`, `additionalProperties`, `items`, `enum`, `const`, `pattern`, `minimum`,
`maximum`, `minLength`, `maxLength`, `minItems`, `maxItems`, `anyOf`, `oneOf`, `$ref` (local).
No third-party validator is needed; the schemas are authoritative for every tool.

Validate anything:

```bash
python3 voice-capability-toolkit/tools-catalog-builder.py validate --input my-file.json
python3 voice-capability-toolkit/tools-voice-profile.py validate --input out/asset-aurora-host-profile.json --schema voice_profile
```

### 4.3 Policy (`asset-policy.json`)

* `origin_policies` — `synthetic-original` (default), `licensed-model` (needs a licence id),
  `authorized-real-person` (needs a consent record covering the requested use).
* `sensitive_domains` — `fraud/harassment/sexual` block; `minors/emergency/politics/finance/
  medical/identity` require review.
* `release_gate` — required manifest fields, required right checks, block conditions.
* `analysis_limits` — the disclaimer text the analysis tool attaches to every report.
* `bounded_execution` — `max_workers 8`, `max_retries 3`, `default_timeout_seconds 180`,
  `max_audio_seconds 3600`, `max_batch_items 500`, `allow_network false`, `allow_shell false`.

Edit these files to change behaviour; no code change is required.

## 5. Safety, consent and approval rules

1. **Original by default.** `origin.type` defaults to `synthetic-original`. A recognizable real
   person requires `authorized-real-person` **plus** a consent record whose scope covers the
   use, project, territory, medium and commercial status — otherwise `check-use` returns
   exit `5` and rendering/publishing should stop.
2. **Impersonation guard.** A request with `imitate_real_person: true` is blocked with the
   reason and the correct path (use an original or licensed profile). It is not silently
   rewritten.
3. **Disclosure.** Profiles advertise `rights.disclosure_required`; renders and manifests carry
   the disclosure text from `asset-policy.json`.
4. **Approval before destructive or publishing actions.** `revoke` and `validate-package
   --release` require `--approve` (or `VOICE_TOOLKIT_APPROVAL_TOKEN` in a pre-approved
   pipeline). Without it they return exit `5` with the action and the dependent-asset count.
5. **Sources are never overwritten.** `repair` and `master` refuse an output path equal to the
   input, and every tool refuses to overwrite an existing output unless `--force` is passed.
6. **Analysis never asserts identity or origin.** Every analysis report carries a
   `confidence_note`; synthetic-speech and accent inference are explicitly out of scope
   (§9), because this build ships no trained detector.
7. **Bounded execution.** No network, no shell, no arbitrary code. Audio is capped at one hour
   per file, batches at 500 items, and every command accepts `--timeout`.

## 6. Exit codes and error shape

| Code | Meaning |
|------|---------|
| 0 | Success |
| 2 | Usage error (bad CLI arguments) |
| 3 | Invalid input (schema violation, unknown preset/provider/op, refusal to overwrite) |
| 4 | Not found (missing file, unknown name, no match) |
| 5 | Blocked (policy, consent, approval gate) |
| 6 | Unavailable (missing optional dependency such as `pypdf`, or unsupported codec) |
| 7 | Unexpected runtime failure (reported with a short traceback) |
| 130 | Cancelled (deadline or Ctrl-C) |

Errors are structured:

```json
{"status": "error", "code": 3, "message": "…", "hint": "…", "details": {...}, "elapsed_seconds": 0.01}
```

## 8. Known limits and unavailable integrations

* **Built-in speech synthesis is formant-based, not neural.** It produces intelligible,
  deterministic, controllable speech (pitch, formant, pace, stress, pauses, emotion mapping,
  effects) but it is not studio-quality TTS. `providers` states this, and `--provider` refuses
  anything except `builtin-formant` (exit `6`) rather than pretending an engine exists.
* **No external model adapters.** Voice conversion, neural TTS, lip-sync, watermarking and
  trained detection need third-party engines. `build` still produces their plans; the runtime
  gates (`check-use`, `verify-consent`) work today.
* **Diarization, VAD, alignment, reverb and artifact detection are heuristics** over signal
  statistics (energy thresholds, autocorrelation pitch, spectral features, k-means). They are
  documented as such in every report and must not be presented as identity or provenance
  proof.
* **No accent/language classifiers and no synthetic-speech detector** ship in this build; the
  tools say so instead of guessing (`attributes.accent_markers.available = false`).
* **No singing/vibrato synthesiser.** Singing plans, melodic timing and mixing are supported;
  actual singing is not generated.
* **No real-time streaming audio device integration.** Chunked/batch rendering is supported;
  live microphone, interruption handling and network transport are not.
* **No media container workflows.** SRT/VTT-style cue sheets and manifests are supported;
  video muxing, EDL/AAF import and lip-sync to picture are not.
* **DSP expectations.** Loudness is BS.1770-style gated measurement with K-weighting; true peak
  is estimated with 4× oversampling. Values agree with themselves across tools but are not
  certified against a reference meter.
* **Codec availability depends on libsndfile.** If MP3/Opus writing fails, the tool exits `6`
  and recommends WAV/FLAC rather than silently degrading.

## 9. Troubleshooting and recovery

| Symptom | Cause | Fix |
|---------|-------|-----|
| `NumPy is required …` (exit 6) | NumPy missing | `python3 -m pip install "numpy>=1.24"` |
| `SoundFile is required …` (exit 6) | SoundFile or libsndfile missing | install `libsndfile1` + `soundfile` |
| `Could not write … MP3` (exit 6) | libsndfile built without the codec | use `--format wav` or `flac` |
| `PDF input requires the optional 'pypdf' dependency` (exit 6) | no `pypdf` | `pip install pypdf` or convert to `.txt/.md` |
| `Refusing to overwrite …` (exit 3) | output exists | pass `--force` or choose another path |
| `Approval required …` (exit 5) | destructive/release action | review, then `--approve` (or set `VOICE_TOOLKIT_APPROVAL_TOKEN`) |
| `Requested use … outside the consent scope` (exit 5) | consent does not cover the use/project/territory/medium | obtain a broader consent record; do not edit the scope to fit |
| `No capability matched …` (exit 4) | lookup keyword too narrow | try a single keyword (`sing`, `loudness`, `consent`) |
| `Catalog contains no categories` (exit 3) | input had no recognizable structure | use `1. Skill Name: X` + `Description: Y`, bullets, or a table; check `--heading-mode` |
| Extraction looks wrong for a PDF | unusual layout | export to `.md`/`.txt`, or pass `--category "<umbrella>"` |
| Long renders time out (exit 130) | deadline hit | raise `--timeout`, shorten the script, or split the brief |
| Loudness keeps drifting | very short clips (< 1 s) | master with `--target-lufs` on the stitched file, not per clip |

Recovery patterns:

* **Resume a batch.** `render-brief` writes one file per segment with
  `--per-segment-files`; re-running with `--force` regenerates only what you ask for, and
  finished segments can be re-concatenated with `tools-audio-delivery.py concat`.
* **Undo a bad repair.** Sources are never modified: re-run from the original input.
* **Revoke a voice.** `revoke --assets-root <dir>` lists every asset referencing the profile
  (with hashes) so dependents can be replaced; the command is approval-gated.
* **Recover a bad manifest.** `package` rebuilds it from the files on disk; `validate-package`
  reports exactly which entries mismatch.

## 10. Extension and maintenance

* **New capability mapping.** Add a rule to `asset-build-recipes.json` (`name_matches`,
  `keyword_rules`) or a new recipe under `recipes`. No code change needed; `build` picks it up.
* **New preset / emotion / style.** Add to `asset-voice-presets.json`. Unknown names fail with
  exit `3`/`4` and list the valid values.
* **New delivery target.** Add an entry to `delivery_targets`; `encode`, `inspect`, `master
  --preset` and `checklist` all use it.
* **New policy rule.** Edit `asset-policy.json` (`sensitive_domains`, `release_gate`,
  `origin_policies`).
* **New schema.** Add a `$defs` entry in `asset-schemas.json`; validate with
  `tools-catalog-builder.py validate --schema <name>`.
* **New provider (e.g. a neural TTS service).** Implement
  `render(text, settings) -> (audio, samplerate)` and register it in
  `cmd_render` in `tools-audio-synthesis.py`; keep credentials in environment variables and
  never in this folder. Keep the `providers` command honest about what is available.
* **New checklist.** Add to `asset-checklists.json` with a measurable rule and the command
  that measures it.
* **Versioning.** `TOOLKIT_VERSION` lives in `tools-runtime-common.py`; every result envelope
  carries it, so downstream automation can pin behaviour.
