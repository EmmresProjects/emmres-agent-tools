1. Orchestration, Planning, and Work Splitting
1. Powerful Work Splitter
Evaluates every request before execution and decides whether one response is sufficient or staged
work is safer. It scores scope, file volume, dependencies, tool calls, uncertainty, and verification
burden; recommends a prompt count; asks the user to accept or override that count; labels each stage
X of Y; pauses at checkpoints; accepts Continue or equivalent; and permits the user to expand or
reduce Y midstream. It checks stage completion, remaining dependencies, uploaded-file availability,
and whether the final stage includes assembly and polish. It returns an approved stage plan, checkpoint
state, continuation instruction, and a verified final package.
2. Single-Prompt Feasibility Assessor
Determines whether a task can be completed well in one response. It compares required artifacts,
context size, tool limits, risk, and validation steps against a single-turn budget. It checks all requested
outputs can be created and checked without deferring essential work. It returns a one-turn decision
with reasons and a fallback staged plan.
3. Adaptive Prompt Count Estimator
Recommends the number of execution stages. It converts work packages, review gates, file groups, and
integration steps into a practical count and recalculates it when scope changes. It checks the count is
neither artificially inflated nor too small for safe verification. It returns recommended, minimum, and
user-selected stage counts.
4. User-Controlled Stage Negotiator
Lets the user choose a different stage count from the recommendation. It rebalances workload and
quality gates across the chosen count without dropping requirements. It checks every requirement still
has an owner stage and final verification. It returns a revised stage map and explicit trade-offs.
5. Checkpoint and Continue Controller
Stops at safe boundaries and resumes only after the user signals continuation. It recognizes Continue,
proceed, go on, next, and equivalent intent while rejecting ambiguous scope-changing replies. It checks
saved state identifies completed work, current files, next actions, and blockers. It returns a concise
checkpoint receipt and the next completed stage.
6. Dynamic Stage Expansion Manager
Extends an active plan when the user requests more stages or new complexity appears. It preserves
completed stages, renumbers future stages, redistributes remaining work, and adds new validation
gates. It checks prior output remains compatible with the expanded plan. It returns an updated X of Y
plan with no lost work.
7. Dynamic Stage Compression Manager
Compresses an active plan when the user wants fewer stages. It merges compatible work packages
while protecting critical checks and final assembly. It checks no safety, accuracy, or deliverable
requirement is silently removed. It returns a compressed plan and disclosed quality trade-offs.
8. Dependency-Aware Task Decomposer
Breaks a goal into atomic, ordered work packages. It maps prerequisites, parallel branches, shared
inputs, and integration points. It checks each package has clear inputs, outputs, pass conditions, and
successor links. It returns a dependency graph and executable sequence.
9. Parallel Workstream Coordinator
Identifies independent branches that can run in parallel. It separates research, drafting, coding, media,
and validation streams and defines merge contracts. It checks parallel outputs use compatible names,
schemas, and versions. It returns a parallel execution map and merge plan.
10. Critical Path Scheduler
Prioritizes tasks that control total completion time. It estimates duration, uncertainty, blockers, and
downstream impact. It checks critical dependencies are completed before optional polish. It returns a
critical path, buffer plan, and escalation triggers.
11. Milestone Gatekeeper
Prevents later work from starting before required evidence exists. It applies entry and exit criteria to
discovery, build, test, and release stages. It checks gate evidence is concrete and reproducible. It
returns pass, repair, or blocked status with next action.
12. Final Assembly Orchestrator
Combines outputs from all stages into one coherent result. It resolves duplication, naming conflicts,
formatting drift, broken references, and missing sections. It checks the assembled artifact opens
correctly and satisfies the original request. It returns a polished final package and completion
summary.
2. Intake, Scope, and Requirement Control
1. Intent Resolver
Finds the user's real desired outcome from incomplete or informal instructions. It translates goals,
constraints, examples, and exclusions into testable requirements. It checks assumptions are minimal,
explicit, and reversible. It returns an outcome statement and requirement set.
2. Requirement Ledger
Maintains a living list of every explicit and implied requirement. It assigns identifiers, owners, status,
evidence, and acceptance tests. It checks nothing is lost during revisions or multi-stage work. It returns
a traceable requirement-to-output matrix.
3. Constraint Extractor
Detects limits on format, length, tools, tone, jurisdiction, time, and audience. It separates hard
constraints from preferences and examples. It checks conflicts and impossible combinations are
surfaced early. It returns a prioritized constraint register.
4. Ambiguity Triage
Decides which uncertainties can be safely assumed and which require a question. It measures impact,
reversibility, and risk before interrupting the user. It checks questions are asked only when answers
materially change the result. It returns a resolved assumption list or one focused clarification.
5. Success Criteria Designer
Converts broad quality goals into observable pass conditions. It defines correctness, completeness,
usability, presentation, and handoff checks. It checks criteria can actually fail and are not vague praise.
It returns an acceptance checklist.
6. Scope Boundary Guard
Prevents accidental expansion or omission. It tracks in-scope, out-of-scope, deferred, and newly
requested work. It checks changes are reflected in schedule and stage count. It returns an updated
scope baseline.
7. Change Request Integrator
Processes mid-project additions, removals, and substitutions. It assesses impact on files, dependencies,
tests, and completed work. It checks the change does not silently invalidate prior stages. It returns a
revised plan and affected-item list.
8. Assumption Register
Records provisional decisions made under missing information. It links each assumption to impact,
evidence, and a trigger for rechecking. It checks temporary guesses are not treated as facts. It returns
a reviewable assumption log.
9. Acceptance Test Author
Writes practical tests for each deliverable. It covers normal, boundary, failure, recovery, accessibility,
and clean-state use. It checks tests map directly to requirements. It returns an executable or
inspectable test plan.
10. Definition-of-Done Enforcer
Blocks completion claims until all required artifacts and checks pass. It verifies content, structure,
packaging, naming, and reopenability. It checks partial work is labeled accurately. It returns a
completion decision with remaining defects if any.
3. File Intake, Recovery, and Asset Management
1. Universal File Intake
Inventories all attached and generated files before work begins. It records name, type, size, readability,
duplication, and intended use. It checks every referenced file is present and accessible. It returns a file
inventory and processing plan.
2. Missing File Detector
Finds files mentioned by the user but unavailable to the agent. It compares instructions, links,
manifests, and attachment inventory. It checks work does not proceed on fabricated content. It returns
a precise re-upload request naming each missing file.
3. Corrupt File Triage
Diagnoses unreadable or damaged files without overwriting originals. It checks signatures, containers,
embedded relationships, encoding, and recoverable content. It checks recovery preserves the source
and documents limitations. It returns a repaired copy or actionable recovery report.
4. Re-Upload Recovery Coordinator
Restores interrupted work after a file is uploaded again. It matches the replacement to prior state,
revalidates dependencies, and reruns affected checks. It checks stale results from the missing version
are not reused. It returns a resumed plan from the exact safe checkpoint.
5. Archive and Package Extractor
Safely inspects ZIP, TAR, and nested packages. It prevents path traversal, inventories contents, and
preserves directory structure. It checks expected files exist and suspicious entries are isolated. It
returns an extraction directory and manifest.
6. File Format Identifier
Identifies actual format rather than trusting the extension. It uses magic bytes, container structure, and
parse tests. It checks mislabeled or unsupported files are flagged. It returns a verified format map.
7. Duplicate and Version Resolver
Detects duplicate, near-duplicate, and conflicting versions. It compares hashes, metadata, content, and
modification history. It checks the selected source of truth is explicit. It returns a deduplicated set and
version decision.
8. Asset Naming Normalizer
Applies consistent, portable file and folder names. It removes unsafe characters, resolves collisions, and
preserves extensions. It checks links and scripts still resolve after renaming. It returns a normalized
asset tree and rename map.
9. Cross-File Reference Validator
Checks links among documents, sheets, slides, code, and media. It finds broken paths, missing
relationships, and stale references. It checks all internal dependencies resolve in the final package. It
returns a reference repair report.
10. Clean-State Package Tester
Copies the deliverable into a clean location and opens or runs it there. It detects hidden dependencies
on temporary paths, caches, or local settings. It checks the recipient can use the package
independently. It returns a clean-state pass result.

1. Research Question Builder
Turns a broad topic into answerable subquestions. It defines evidence needs, date range, geography,
source hierarchy, and exclusions. It checks subquestions collectively cover the decision. It returns a
scoped research plan.
2. Authoritative Source Finder
Prioritizes primary and official sources. It locates standards, laws, product documentation, datasets,
and original studies. It checks sources are current enough and directly support claims. It returns a
source set with relevance notes.
3. Multi-Source Evidence Synthesizer
Combines findings without flattening disagreements. It compares definitions, methods, dates,
populations, and confidence. It checks conflicts and gaps remain visible. It returns a balanced synthesis
with claim-level support.
4. Claim Verification Auditor
Tests each important factual claim against evidence. It checks names, dates, numbers, quotations, and
causal wording. It checks unsupported claims are removed or clearly qualified. It returns a verified
claim ledger.
5. Source Freshness Monitor
Detects when time-sensitive evidence may be stale. It checks publication date, update date, version,
and superseding notices. It checks current claims use current sources. It returns a freshness status and
refresh list.
6. Citation Integrity Checker
Ensures citations point to the correct supporting material. It checks source identity, locator, quotation
fidelity, and claim scope. It checks citations are neither decorative nor misplaced. It returns a corrected
citation set.
7. Conflicting Evidence Resolver
Analyzes credible disagreement rather than choosing silently. It identifies methodological,
jurisdictional, temporal, and definitional causes. It checks the final conclusion reflects uncertainty
honestly. It returns a conflict matrix and bounded conclusion.
8. Dataset Provenance Tracker
Records where data came from and how it changed. It captures source, license, retrieval date, filters,
transformations, and joins. It checks results can be reproduced. It returns a provenance record and
transformation chain.
9. Literature Gap Mapper
Finds unanswered areas and weak evidence. It classifies missing populations, methods, variables,
replications, and time periods. It checks gaps are distinguished from search failure. It returns a
prioritized gap map.
10. Research Brief Producer
Converts evidence into a decision-ready brief. It summarizes findings, confidence, trade-offs,
implications, and next steps. It checks every major recommendation traces to evidence. It returns a
concise research brief.
5. Knowledge, Context, and Memory
1. Context Window Curator

requirements, decisions, interfaces, and blockers. It checks critical details survive summarization. It
returns a stage-ready context packet.
2. Long-Project State Keeper
Maintains continuation state across pauses. It stores completed stages, open issues, file versions,
decisions, and next commands. It checks resumption does not repeat or contradict prior work. It
returns a durable project snapshot.
3. Decision Memory Manager
Stores decisions with the conditions that made them valid. It records alternatives, rationale, evidence,
owner, date, and reversal triggers. It checks outdated decisions are rechecked when conditions change.
It returns a decision register.
4. Preference Learner
Applies stable user preferences without overgeneralizing. It separates durable preferences from one-
time requests. It checks current instructions always override remembered defaults. It returns a
personalized but controllable output profile.
5. Knowledge Deduplicator
Merges repeated notes and overlapping facts. It preserves exceptions, provenance, and the strongest
wording. It checks important nuance is not erased. It returns a compact canonical knowledge base.
6. Contradiction Detector
Finds incompatible statements across instructions and files. It classifies direct conflict, scope
difference, version difference, and apparent conflict. It checks material conflicts are resolved before
execution. It returns a contradiction report and chosen rule.
7. Terminology Controller
Maintains consistent names, acronyms, and definitions. It creates a glossary and checks every artifact
for drift. It checks domain terms remain accurate and audience-appropriate. It returns a controlled
vocabulary.
8. Context Drift Monitor
Detects when later work diverges from the original goal. It compares stage outputs to the requirement
ledger and success criteria. It checks drift is repaired before final assembly. It returns a drift alert and
correction plan.
9. Handoff Context Packager
Prepares all information another agent or person needs to continue. It includes state, files, commands,
decisions, risks, and next tests. It checks the recipient can continue without rediscovery. It returns a
concise continuation packet.
10. Memory Privacy Filter
Prevents sensitive or temporary information from becoming durable memory. It classifies data by
sensitivity, purpose, retention, and user intent. It checks only appropriate information persists. It
returns a sanitized memory update.

10. Localization Writer
Adapts meaning for a target language and culture. It handles locale, idioms, dates, units, politeness,
